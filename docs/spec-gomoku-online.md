## 1. 目的
五目並べに **部屋作成＆共有方式のオンライン2人対戦**を追加する。ログイン（Google認証等）は使わず、部屋コード/リンク共有で参加。スコープは **MVP＋再接続＋観戦**。

## 2. アーキテクチャ
- 静的サイト（GitHub Pages）＋ **PartyKit サーバー（Cloudflare Durable Objects ベース）** の構成。既存 ranking-worker と同様、バックエンドは別デプロイ。
- **部屋 = 1つの Party（DOインスタンス）**。各部屋がWebSocketで参加者を束ね、盤面状態を**権威的に保持・検証**する。
- 通信量が極小（ターン制）なので Cloudflare 無料枠で実質$0。WebSocket Hibernation を使う。

### コンポーネント
- `party/` 新規ディレクトリに PartyKit サーバー（`server.ts` 等）。
- クライアントは index.html の五目並べに「オンライン対戦」モードを追加し、PartyKit クライアントSDK（または素のWebSocket）で接続。
- `checkGomoku` はクライアント／サーバー双方に同一ロジックを置く（サーバーが着手を検証）。**両者を必ず一致させる**（divergence厳禁）。

### 設定
- index.html の `PGP_CONFIG` に `partyHost`（PartyKit のデプロイURL）を追加。未設定（空）ならオンラインモードは「準備中」表示でグレースフルに無効化。

## 3. 機能要件

### A. 部屋作成・参加 — Must
- [ ] 五目並べのセットアップ画面に「🌐 オンライン対戦」を追加 → 「部屋を作る」「部屋に参加（コード入力）」。
- [ ] 部屋作成で**短い部屋コード**（例: 5〜6文字英数）を発行。共有用に `?room=CODE` のリンクとコードを表示（コピー導線）。
- [ ] `?room=CODE` 付きでサイトを開いたら、その部屋へ自動参加（五目並べのオンラインモードに直行）。
- [ ] 接続状態（接続中/相手待ち/対局中/切断）を表示。

### B. 対局同期・権威検証 — Must
- [ ] 座席割当：作成者=**黒（先手）**、参加者=**白（後手）**。3人目以降は**観戦者**。
- [ ] 着手はサーバーへ送信 → サーバーが「**今の手番の席のプレイヤーか／空きマスか／盤内か**」を検証して受理 → 全員に新状態をブロードキャスト。クライアントは権威状態で再描画。
- [ ] 勝敗・引き分けはサーバー側 `checkGomoku` で確定し配信。勝ち筋ハイライトも同期。
- [ ] もう一局：両者合意でリセット。**先手後手を入れ替え**て再開。

### C. 再接続 — Must（スコープ拡張分）
- [ ] プレイヤーは席トークン（localStorage 保存）を持ち、リロード/一時切断後に**同じ席で復帰**できる（一定の猶予時間内）。
- [ ] 復帰時はサーバーの権威状態を受信して盤面を完全復元。

### D. 観戦 — Must（スコープ拡張分）
- [ ] 3人目以降は読み取り専用で**ライブ観戦**（着手・勝敗をリアルタイム受信）。着手不可。
- [ ] 席が空いた場合の昇格は MVP では行わない（観戦は観戦のまま）。Could で検討。

### E. プレイヤー名 — Must
- [ ] 参加時に**ランダムな表示名**を既定で付与（例: 「あかいキツネ」「あおいクマ」のような形容＋動物の可愛い自動生成）。
- [ ] その名前を**ユーザーが変更可能**（入力欄で編集／「サイコロ」で別のランダムに振り直しも可）。
- [ ] 名前は localStorage に保存し次回も既定で復元。サーバーへ presence として送り、**両席（黒/白）と相手に名前を表示**。観戦者数も表示（名前は任意）。
- [ ] 名前は表示専用（認証ではない）。長さ制限・簡単なサニタイズ（改行/極端な長さを弾く）を行う。

### Should
- [ ] 相手の接続/切断トースト表示、手番の明示、待機中アニメ。
- [ ] 簡単な部屋一覧やランダムマッチは**やらない**（共有方式に限定）。

## 4. UI/UX
- オンラインモードのUI（部屋コード/リンク・接続状態・席表示・観戦表示）は既存トーン（cqwスケール・配色）で。
- ローカルの 2人/CPU モードはそのまま残す。オンラインは並列の選択肢。

## 5. セキュリティ/不正対策
- サーバーが**全着手を検証**（手番・空きマス・盤内）。クライアントを信用しない。
- 部屋コードは推測されにくいランダム。観戦者は着手イベントを送れない（サーバーが拒否）。

## 6. 守ること（厳守）
- 既存5ゲーム（tea/lane/spot/ox/gomoku のローカル挙動）を壊さない。回帰必須。
- オンラインは追加モード。`partyHost` 未設定でも既存機能・ローカル対戦は完全動作。
- index.html を変更するので sw.js の **CACHE_VERSION を必ず上げる**。
- クライアント／サーバーの `checkGomoku` を一致させる。

## 7. デプロイ・人手が必要な手順（実装後）
- PartyKit/Cloudflare アカウント（ranking-worker と同じCFアカウント可）。
- `party/` を `npx partykit deploy`（要ログイン）。発行されたURLを `PGP_CONFIG.partyHost` に設定して index.html を更新→公開。
- ローカル開発は `npx partykit dev`。
- ※ デプロイとアカウント連携は**ユーザー操作が必要**（エージェントはコードまで）。手順書を README/docs に残す。

## 8. テスト観点
- 2ブラウザ（または2タブ）で部屋作成→参加→対局→勝敗→もう一局。
- 着手検証：手番でない側・埋まったマス・盤外・観戦者の着手がサーバーに拒否される。
- 再接続：一方をリロードしても同じ席で復帰し盤面一致。
- 観戦：3つ目の接続が読み取り専用でライブ反映。
- `partyHost` 未設定時にオンラインが「準備中」で、ローカル機能は無傷。
- 回帰：既存5ゲーム＋ローカル五目並べ（2人/CPU/ヒント/待った）が従来通り。
