## 1. 目的
公開済みの五目並べ（gomoku）の対戦体験を改良する。3点：
1. **待った**（直前1手を戻す）
2. **ヒントボタン**（オンデマンドで良手を1つ提案・盤上に表示）
3. **メニューの「？」アイコン不具合修正**

## 2. 方針
- gomoku ゲーム内に閉じて実装するのが基本（versusコア・既存ゲームに極力触れない）。
- 待った／ヒントのボタンは gomoku の canvas に描画し、`onDown(x,y)` のヒットテストで処理（既存のリセット処理と同じパターン。コア改変なし）。
- **index.html を変更するので sw.js の `CACHE_VERSION` を必ず1つ上げる**（例: pgp2-v5 → pgp2-v6）。

## 3. 機能要件

### A. 待った（1手戻す）— Must
- [ ] 着手を履歴スタックに積む（index と手番）。
- [ ] 「待った」ボタンで**直前の1手**を取り消し、手番を戻す。
- [ ] 連打防止：直前1手のみ戻せる（2手連続では戻さない＝シンプル仕様）。履歴が空なら無効（淡色表示）。
- [ ] 決着後の勝ち手も戻せる（誤タップ救済）＝戻したら決着状態も解除して続行可能に。
- [ ] リセットで履歴クリア。

### B. ヒントボタン — Must
- [ ] 「💡 ヒント」ボタンで、現在の手番の**良手を1つ**算出し、盤上の該当交点を**点滅ハイライト**（数秒）。自動着手はしない。
- [ ] 良手算出は純関数 `getGomokuHint(board, mark) -> index`。優先順位：
  1. 自分が5を完成できる点
  2. 相手が次に5を作る（四＝あと1で5）のを止める点
  3. 自分の四を作れる点（三→四の伸ばし含む）
  4. 相手の活三を止める点
  5. フォールバック：既存石の近傍で中央寄りの空き
- [ ] `getGomokuHint` は副作用なし。**将来の `getGomokuCpuMove(board, mark)` のたたき台**として流用できる形にする（コメント明記）。

### C. メニュー「？」アイコン修正 — Must
- [ ] 各ゲームカードの「？」をタップしたら確実に遊び方（howto）が開くようにする。
- [ ] 現状の不具合想定＝スマホで `?` の当たり判定が小さくカード全体タップに負ける。対策：**`?` のタップ領域を拡大**し、**`?` の click で `e.stopPropagation()` し、明示的に `openGame(def,{forceHowto:true})` を呼ぶ**（カード本体の遷移と分離）。
- [ ] solo/versus 全カードで動作（ox/gomoku 含む）。

## 4. UI/UX
- 待った／ヒントボタンは gomoku 盤面画面に配置。既存 `#btnQuit`（左上✕）や盤に被らない位置（例：盤の下の余白）に、既存トーンで小さめに。
- ヒントのハイライトは石と区別できる色／リング点滅。
- 「？」はタップ領域を広げつつ見た目は維持。

## 5. 守ること（厳守）
- 既存5ゲーム（tea/lane/spot/ox/gomoku の既存挙動）を壊さない。回帰必須。
- コア改変は「？」ハンドラの分離程度に限定。待った/ヒントは gomoku 内で完結。
- 1ファイル方針。sw.js の CACHE_VERSION を上げる。

## 6. テスト観点
- `getGomokuHint`：勝ち点検出／相手四ブロック／四作り／三ブロック／フォールバックの各ケース、空盤・終盤で例外なし。
- 待った：1手戻し・手番復帰・決着解除・履歴空時の無効・リセットでクリア。
- 「？」：solo/versus 全カードで howto が開く（スマホ実機タップ）。
- 回帰：tea/lane/spot/ox と gomoku の通常対戦が従来通り。
- 表示：スマホで待った/ヒントボタン・ハイライトが崩れない。
