## 1. 背景・目的

### 解決したい課題
- 既存ゲーム（tea / lane / spot）は全て「25秒・1人・スコア稼ぎ」型。バリエーションが単調。
- 2人で遊べる対戦ゲームが無い。三目並べで「対戦」という新ジャンルを追加する。
- 同時に、今後の対戦ゲーム量産に耐える**第2のゲーム種別（versus）**の土台を作る。

### 期待する効果
- 既存の演出・画面遷移・PWAをそのまま使い回しつつ、対戦ゲームを足せるようになる。
- 三目並べはVer1.0では2人対戦のみ。**将来CPU対戦を関数1つ差し込むだけ**で実現できる構造にする。

---

## 2. 採用方針（パターンB）

既存エンジンは `registerGame({...})` で登録するプラグイン方式だが、**タイマー・スコア・コンボ・フィーバー・デイリー・スコア付きシェア**を全て「時間制スコアゲー」前提で持っている。三目並べ（ターン制・スコア無し・勝敗のみ）はこの規格に合わない。

そこで **`type:'versus'` をエンジンに導入**し、versus種別のときはスコア系の仕組みをスキップする分岐を入れる。これにより：

- 1ファイル構成・既存デザイン・画面遷移（タイトル→選択→ゲーム）を完全再利用
- 今後の対戦ゲームは全て `type:'versus'` で量産可能
- コア改変は「分岐の追加」のみで、既存3ゲームの挙動は一切変えない

## 3. 機能要件

### Must（必須 / Ver1.0）
- [ ] 3×3＝9マスの盤面
- [ ] 2人対戦（○と×を交互に配置）
- [ ] 縦・横・斜めで3つ揃ったら勝利、勝ち筋をハイライト
- [ ] 引き分け（9マス埋まって勝者なし）判定
- [ ] リセット／もう一度ボタン
- [ ] スマホ対応（タップ操作・既存の縦型ステージに収まる）
- [ ] 既存3ゲームの挙動・スコア・ランキングに影響を与えない

### Should（できれば）
- [ ] 手番表示（HUD：「○のばん」「×のばん」）
- [ ] 勝利時の演出（既存 confetti / banner の流用）
- [ ] 簡単な遊び方（howto）表示

### Could（将来 / Ver2.0以降）
- [ ] CPU対戦（弱・強）。`getCpuMove(board, mark)` を差し込むだけにする
- [ ] 先手後手の選択、O/X外観のスキン

## 4. 技術仕様

### 使用技術
- 既存と同じ：単一HTML＋Vanilla JS、canvas描画（`#cv`）、入力はコア集約（`onDown`）
- ビルド・追加ライブラリ無し（既存方針を踏襲）

### ファイル構成（変更後）
```
petit-game-park/
├── index.html        ← エンジンに versus 分岐を追加 ＋ 末尾に registerGame で三目並べ登録
├── docs/
│   └── spec-tic-tac-toe.md   ← 本仕様書（新規）
└── （その他は変更なし）
```
※ 単一ファイル方針のため新規jsファイルは作らない。三目並べは index.html 末尾の「ミニゲーム登録ゾーン」に追記する。

### コア（エンジン）への変更点 — これだけ

| 関数 | 変更内容 | 理由 |
|------|---------|------|
| `makeCtx()` (701行付近) | 戻り値に `type:def.type` を追加 | ゲーム側が種別を知れるように |
| `openGame()` (717行付近) | `def.type==='versus'` のとき：スコア/ベストHUDを非表示、`#hudTimeBar` 非表示、カウントダウンを省略して `phase='play'` へ直行（または「GO!」のみ） | versusはスコア・制限時間が無い |
| `hudUpdate()` (既存) | 変更ほぼ不要。`duration` 無し時は既に `game.hudInfo()` を表示する分岐があるので、versusは `hudInfo()` で手番を返す | 既存の仕組みを流用 |
| `startLoop()` (780行付近) | **変更不要**。`if(curDef.duration&&...)timeUp()` で既にガードされており、duration未設定なら自動終了しない | 既存の安全設計を活用 |
| `buildCards()` (選択画面) | versusカードもループで自然に並ぶ（既存ループのまま）。必要なら対戦バッジ表示だけ追加 | 最小変更 |

> 結果画面（`showResult`）はスコア専用なので **versusでは呼ばない**。三目並べは勝敗・引き分け・もう一度をcanvas上（既存 `banner()` 併用）で完結させ、`✕`ボタンで選択画面に戻る。これにより `showResult` には一切手を入れない。

### 三目並べのゲーム定義（`registerGame`）
```
registerGame({
  id:'ox', emoji:'⭕', title:'まるばつ たいせん', desc:'2人で あそぶ ○×ゲーム',
  color:'#ffd6a5', type:'versus',   // ← duration は付けない
  howto:[['👆','マスを タップして ○×を おく'],['🏆','タテ・ヨコ・ナナメで 3つ そろえたら かち！']],
  create(ctx){ ... }
})
```

### create(ctx) が実装するメソッド（既存コントラクト準拠）
- `onDown(x,y)` … 盤面座標→セル変換、空きなら着手、手番交代、勝敗チェック。決着後タップでリセット
- `draw(g)` … 盤面グリッド・○×・勝ち筋ハイライト・決着テキスト・リセットボタンを描画
- `hudInfo()` … 手番／結果文字列を返す（HUDのタイマー枠に表示）
- `update(dt)` … 演出用（必須でなければ no-op 可）
- `destroy()` … 後始末（任意）

### 将来CPU対応のための構造（Ver1.0で仕込むだけ）
- 勝敗判定は**純関数** `checkWin(board) -> {winner, line}` に分離（自動テスト対象）
- 着手を `place(cell)` に集約し、手番交代を1箇所に
- プレイヤー定義を `players=[{mark:'○',type:'human'},{mark:'×',type:'human'}]` のように持たせ、Ver2.0で `type:'cpu'` を足し `getCpuMove(board, mark)` を呼ぶだけにする

## 7. テスト観点
- **自動テスト**：`checkWin()` の純ロジック（8勝ち筋×○×、引き分け、未決着）

- **回帰**：既存3ゲームのスコア・タイマー・ランキング・デイリーが従来通り動くこと
- **表示**：スマホ実機で盤面が崩れない、タップ判定が正確
